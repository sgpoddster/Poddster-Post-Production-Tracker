Key Data Flows

🗓 New Project (Manual)
1. Admin clicks + New Project
2. Optionally browses Google Calendar → picks booking → fields pre-filled via calendarParser.ts
3. Fills in client name/code manually (not in calendar data)
4. Submits → POST /api/projects/create
5. Job ID generated (5-char hex). One row per episode + per highlight
6. Status = pending_trigger · appears in Awaiting Trigger
🤖 Automated Ingest (GAS)
1. GAS syncs Google Calendar → Sheets
2. For each new booking with edit services, GAS calls:
  POST /api/bookings/ingest with x-api-key header
3. Upserts on internal_id — safe to run repeatedly
4. Status = pending_trigger
▶️ Trigger → Deadline Set
1. POST /api/projects/[id]/trigger
2. Admin can pass a past submittedDate to backdate
3. Project → active
4. V1 version row created:
  due_date = submittedDate + 5 working days
5. Countdown timer starts ticking on dashboard + queue
🔄 Revision Cycle
1. Editor marks done → in_client_review
2. Admin clicks Start Revision:
  POST /api/projects/[id]/revision
3. New version row (V2, V3…) created
  due_date = today + 3 working days
4. Status → in_revision · current_version bumped
5. Frame.io filename auto-updates to new V#
📋 Frame.io Filename
Built by buildOutputFilename() in utils.ts
A3F2BE1  2pm  7th May 2026  -  V1
= internal_id + start time + ordinal date + version
"Copy filename" button on project detail page
Tooltip previews before copy · flashes ✓ on success
⏸ On Hold / Resume
Hold: POST /hold → saves hold_date, freezes timer display
Resume: POST /resume →
  daysPaused = today − hold_date
  due_date += daysPaused (calendar days)
  on_hold = false, hold_date = null
Admin only · amber button when active
